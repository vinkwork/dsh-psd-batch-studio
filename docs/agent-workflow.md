# Agent 工作流：把「模板 + 需求表」跑成主图

> 这是把本引擎当成 **命令行工具 / 任意 agent 宿主** 使用时的目录约定与操作手册。
> 如果你是在 dsh 里用面板，看 [README](../README.md) 的「插件用法」即可。
> 这份文件原名 `AGENTS.md`，放在你的**项目根目录**（不是仓库根）时，Claude Code / Codex /
> dsh 这类 agent 会自动读取。

（以下内容原样搬运自工作目录里的 `AGENTS.md`，可以整段拷到你的项目根目录。）

你在帮业务同学把「PSD/PSB 模板 + 需求表」批量做成电商主图（JPG）。用户多半不懂技术：用大白话沟通，先做再说明，不要让用户去看 JSON 或命令。

## 目录约定（项目根目录 = 工作目录）

按「分类 / 案例名」组织：每个分类文件夹下，一个案例（一次活动或一个模板的一套素材）对应一个同名子文件夹。随项目附带的 **示范案例** 就是完整样例，新案例照它的样子建。

| 分类文件夹 | 里面放什么（在 `<案例名>/` 下） | 谁改 |
|---|---|---|
| `模板/` | PSD/PSB 模板。**只读，绝不修改、移动、覆盖** | 设计师 |
| `规则/` | `<模板名>.rules.json`。图层对应、字体字号、赠品档位都在里面 | 你起草，设计师确认 |
| `需求表/` | `需求表.xlsx`（sheet 名「主图」）。空白样板是 `需求表/需求表模板.xlsx` | 业务 |
| `产品图/` | 产品抠图，文件名 = 需求表「产品名称」+ 扩展名，**必须完全一致** | 业务 |
| `赠品图/` | 赠品抠图 | 业务 |
| `字体包/` | 模板用到的字体文件（PSD 只存字体名，不存字体）。案例下没有就用 `字体包/` 根目录里的 | 设计师 |
| `说明图/` | 业务规则说明图（如「主图修改说明.png」）。**先读它** | 业务 |
| `输出/` | 成品。每次一个自动命名的子文件夹，不会覆盖旧的 | 工具 |
| `引擎/` | 程序，不要改。踩坑记录在 `经验手册.md` | — |

例：案例「示范案例」的文件就是 `模板/示范案例/模版-1-优化.psb`、`规则/示范案例/模版-1.rules.json`、`需求表/示范案例/需求表.xlsx`、`产品图/示范案例/…`、`输出/示范案例/样张-…/`。

**新建案例**（用户说「新建一个 xxx 活动」）：在 模板、规则、需求表、产品图、赠品图、说明图 各建一个 `xxx` 子文件夹（输出和字体包可以不建，输出会自动建），把 `需求表/需求表模板.xlsx` 复制为 `需求表/xxx/需求表.xlsx`，然后告诉用户把模板、产品图、赠品图、说明图分别放到哪里。多个活动共用同一个模板时，不用复制模板，出图时用 `--template`、`--rules` 指向已有文件即可。

**每条命令都要带 `--case 案例名`**（只有一个案例时可省略）。用户没说案例名时，先问是哪个案例。

## 命令（都在项目根目录运行，用 Bash）

```
node 引擎/bin/psd.mjs preflight --case 示范案例                      # 预检：缺图、名字对不上
node 引擎/bin/psd.mjs draft --case 示范案例                          # 只看模板，起草 规则/示范案例/X.rules.json
node 引擎/bin/psd.mjs render --case 示范案例 --limit 2               # 样张（2 张）
node 引擎/bin/psd.mjs render --case 示范案例                         # 批量
node 引擎/bin/psd.mjs render --case 示范案例 --skus 100212974650,100212974638   # 只重做某几个
node 引擎/bin/psd.mjs view --case 示范案例 --image 输出/示范案例/…/xxx.jpg --crop 0,0,700,400 --scale 2   # 放大看细节
node 引擎/bin/psd.mjs check --case 示范案例                          # 文字层重绘对照（检查字号/位置偏差）
```

可选参数：`--template`、`--rules`、`--sheet` 指向别的案例的文件；`--format png`；`--strict-fonts`（缺字体就报错而不是警告）。
第一次使用先确认环境：`node -v` 需要 ≥ 20，`引擎/node_modules` 不存在就在 `引擎/` 里执行 `npm install`。
运行 `node 引擎/bin/psd.mjs help` 可看全部参数。

如果你的宿主已经装了 `dsh-psd-batch-studio` 插件（DeepSeek Harness），也可以直接用工具 `psd_apply_sheet` / `psd_draft_rules` / `psd_view` / `psd_text_check`，参数含义与上面命令一致（路径要写完整，如 `产品图/示范案例`）。命令行方式在任何宿主都能用。

## 标准流程（必须按序，不要跳步）

### A. 已有规则的案例（`规则/<案例名>/` 里有 .rules.json）
1. **预检**：`preflight`。有 ❌ 就停下，用大白话告诉用户缺什么、该怎么补（缺哪个商品的图、哪两个名字对不上）。**禁止自己挑一张相近的图**，也不要改需求表或改文件名来"凑"。ℹ️ 开头的只是提示，不阻塞。
2. **样张**：`render --limit 2`。用 `Read` 打开输出里的 JPG 和 `contact-sheet.jpg`，**自己先看一遍**（文字有没有被截断、有没有压到别的元素、价格是否红色、小数点是否变小、赠品图是否居中不变形），再把路径给用户确认。
3. 用户说可以后，**批量**：去掉 `--limit`。
4. 读输出目录的 `report.json` 和命令输出：失败的 SKU 单独用 `--skus` 重跑；把成功/失败清单和输出目录告诉用户。

### B. 只有模板、没有规则（常见）
1. `draft --case <案例名>`，得到规则草稿和 `unresolved` 清单。草稿已经能确定：图层角色、商品位、字体字号、赠品区位置、校验区域、图标显隐。
2. **读 `说明图/<案例名>/` 里的图片和需求表里的「说明」行**，补全草稿里 PSD 无法表达的业务规则，直接编辑 `规则/<案例名>/X.rules.json`：
   - 赠品：`gifts.tiers`（满79 / 满129 各送什么、对应哪张赠品图）、`gifts.catalog`（需求表里的赠品名 ↔ `赠品图/` 里的文件，含「\*2」「+」组合写法和别名）。
   - 一级/二级文案规则：一级为 `/` 时二级上提、二级改产品名（这是引擎内置行为，一般无需配置）。
   - 三级文案：说明图只写"按字数调整大小"，默认是「超出模板原宽度就等比缩小」。如果说明图给了具体档位，写进 `type.level3.bins`。
3. **有拿不准的就问用户，一次把问题问完**（例如：说明图里的赠品在 `赠品图/` 里找不到对应图片）。不要猜。
4. 补完后按 A 流程：预检 → 样张 → 用户确认 → 批量。**新模板第一次必须样张确认，不要直接放量。**
5. 规则确认后保留在 `规则/`，以后同一模板直接复用。

### C. 用户说「改一下 xxx」
- 改文案/价格 → 改需求表（先问清楚；改之前复制一份 `需求表/<案例名>/需求表.备份-月日时分.xlsx`），重跑对应 SKU。删商品行同理，先征得同意。
- 改字号/位置/颜色/赠品档位 → 改 `规则/<案例名>/X.rules.json`（改前复制一份 `.bak`），重出样张。
- 想核对文字大小和位置是否和原模板一致 → `check --case <案例名>`，结果里 `drift` 表示偏差超限，附带宽度比和偏移像素。
- 绝不改 `模板/` 下的任何文件。

## 业务规则速查（细节以规则文件和说明图为准）
- 一级文案 = 利益点；`/` 时二级上提为一级、二级改为产品名称。数字红色（模板里的色值，不要改），文字黑色；数字与文字是两种字体两种字号。
- 产品名称：字号固定，不随字数变；三级文案：随字数调整大小。
- 价格：小数点后的数字更小。
- 赠品始终展示 2 档：有「买即赠」→ 上买即赠、下满79；买即赠为 `/` → 上满79、下满129。赠品图按框居中、等比缩放，不变形。
- 图标：`NEW新品上市` 换英文部分和中文部分；留空则隐藏角标。
- 输出文件名：`{sku编码}-{产品名称}.jpg`。

## 红线
- 不改 `模板/`；不模糊匹配素材；不把预检的 ❌ 当成"小问题"直接放过；不在对话里索要或写入账号密码。
- 缺字体：命令会给出警告并用回退字体继续，**必须把缺的字体名告诉用户**（出图字形会和模板有差别），请设计师把字体文件放进 `字体包/<案例名>/`。目前已知模板里的 `AuliareRegular`（NEW 角标英文）不在包里。
- 目前已知局限：角标只替换文字（NEW→HOT、新品上市→爆品热卖），底图仍是模板里的樱桃款；「包邮icon」这类没有英文部分的，英文处会保留模板原样的 New，需要设计师提供对应角标素材。换结构不同的新模板，自动起草可能标错图层，样张必须人工看。
- 出现报错先查 `经验手册.md`（编号 E01 起），新坑按下一个编号补充进去。

## 汇报格式（给用户看的）
一句话结论 → 输出位置 → 成功几张 / 失败几张（附原因）→ 需要用户做的事（如果有）。不要贴 JSON，不要说"规范化""mapping"这类内部词。
